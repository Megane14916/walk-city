# 散歩×街づくりゲーム フロントエンド開発計画書

## 1. 目的

ユーザーが「歩数を入力し、報酬を受け取り、田園風の街へ建物を配置し、成長を実感する」一連の体験を、スマートフォン向けReact Webアプリとして実装する。

開発期間は1週間。バックエンドとは `shared-api-contract.md` を境界として並行開発する。

## 2. フロントエンドの担当範囲

- 画面遷移とレスポンシブUI
- 歩数入力、進捗バー、段階報酬の表示
- 20×20グリッドの街描画
- 建物選択、配置プレビュー、移動操作
- 木・池・ロック中土地の表示
- コイン、人口、週間目標の表示
- ランキングと他ユーザーの街の閲覧
- いいね操作
- ローディング、エラー、成功演出
- バックエンドAPIとの接続
- API未完成期間のモック実装

以下はフロントエンドで確定しない。

- 報酬額の最終判定
- コイン残高の確定
- 建物配置の最終検証
- 人口の確定
- 二重報酬・二重いいねの防止

## 4. 画面別の実装

### 4.1 初回設定画面

- ユーザー名入力
- 街の名前入力
- ゲーム説明を3項目以内で表示
- 完了後にホームへ遷移

完了条件:

- 必須項目が空の場合は送信できない
- 保存中は二重送信できない
- APIエラーを画面に表示できる

### 4.2 ホーム画面

- 今日の歩数入力
- 歩数進捗バー
- 1,000/3,000/5,000/8,000歩の報酬カード
- 週間目標 `2/3回` の表示
- コイン、人口、街への導線

完了条件:

- 数値以外、負数、小数を入力できない
- 取得可能、取得済み、未達の3状態を区別できる
- 報酬取得後にコイン表示が更新される
- 同じ報酬を連打できない

### 4.3 街づくり画面

- 20×20のCSS Grid
- 初期10×10以外はロック表示
- 草、木、池、建物をレイヤー表示
- 建物ショップを画面下部へ表示
- 建物選択後、配置可能マスを強調
- マスをタップして確認後に配置
- 配置済み建物をタップして移動

配置モードの状態:

```text
idle
→ selectingBuilding
→ previewingPlacement
→ submitting
→ success または error
→ idle
```

完了条件:

- 木、池、ロック中、建物上を配置候補にしない
- API処理中の二重配置を防ぐ
- API拒否時に仮配置を取り消す
- 再読み込み後も配置が復元される
- `editable=false` では編集操作を一切表示しない

### 4.4 ランキング画面

- 総人口・今週増加のタブ
- 上位20件
- 自分の順位を強調
- 行タップで街訪問
- 空状態、取得失敗状態

### 4.5 街訪問画面

- `TownGrid` を閲覧専用で再利用
- 街名、所有者、人口、いいね数
- いいねボタン
- いいね済み状態
- 自分の街へ戻る導線

## 6. 状態管理

MVPでは大規模な状態管理ライブラリを必須にしない。ページ単位のstateと共通Contextで開始する。

共通状態:

```js
{
  currentUser,
  todayWalk,
  buildingCatalog,
  myTown
}
```

街画面の一時状態:

```js
{
  selectedBuildingType,
  placementMode,
  previewCell,
  selectedPlacedBuilding,
  isSubmitting
}
```

サーバーデータはレスポンスを正とし、配置成功後は返却されたコイン・人口・建物を反映する。

## 7. API未完成期間の進め方

初日に `services/api.js` の関数名と戻り値を確定し、同じインターフェースの `mockApi.js` を作る。

```js
const api = import.meta.env.VITE_USE_MOCK === "true"
  ? mockApi
  : realApi;
```

モックで用意する状態:

- 新規ユーザー
- 3,200歩で報酬取得可能
- コイン不足
- 空きマスへの配置成功
- 木の上への配置失敗
- 他ユーザーの街
- ランキング上位20件

これにより、バックエンド完成を待たずに全画面を作れる。

## 8. ドット絵とレイアウト

- 1マスの表示基準を64pxとする
- 画面幅に合わせてマップ全体を拡大縮小する
- `image-rendering: pixelated` を使用する
- 建物の基準点を各マスの下中央に統一する
- 建物画像の余白と影の方向を揃える
- 木と池は固定地形として表示する
- スマートフォンでは建築ショップを下部固定にする

初期段階では住民アニメーションを実装しない。余裕があれば装飾として追加する。

## 9. 日別計画

- 20×20グリッド
- 中央10×10の開放表示
- 草、木、池、ロック中マス

### Day 3: 自由配置

- 建築ショップ
- 建物選択、配置可能マス強調
- タップ配置、確認モーダル
- 移動操作

成果物: 民家を選んで空きマスへ配置・移動できる。

### Day 4: 歩数と報酬

- 歩数入力
- 段階報酬カード
- 週間目標
- 報酬演出
- コイン・人口表示更新

成果物: 歩数入力から建築資金獲得まで通して操作できる。

### Day 5: 実API結合

- 認証とプロフィール接続
- 歩数、報酬、街API接続
- エラーコードごとの表示
- 再読み込みテスト

成果物: 実データでホームから建築保存まで動く。

### Day 6: 交流とスマホ調整

- ランキング
- 他ユーザーの街
- いいね

成果物: 2ユーザー間で訪問といいねができる。

### Day 7: デモ準備

- 結合テスト

- 演出と見た目の調整

新機能は追加しない。

### Could

- 建築アニメーション

- 住民アニメーション
- 効果音

## 11. テスト項目

- 主要スマートフォン幅で横スクロール事故がない
- タップ対象が小さすぎない
- 歩数に文字、負数、小数を入力できない
- 報酬ボタンを連打しても表示が壊れない
- 木、池、建物、ロック中マスへ配置できない
- APIエラー後もコインと建物が不整合にならない
- 再読み込み後に同じ街が表示される
- 訪問先では編集できない
- いいね済み表示が再読み込み後も残る

## 12. フロントエンド完了条件

デモ用スマートフォンで以下を連続して実行できること。

1. ログインする
2. 3,200歩を入力する
3. 1,000歩と3,000歩報酬を受け取る
4. 民家を購入して任意の空きマスへ置く
5. 人口が増える
6. 再読み込みしても街が残る
7. ランキングから他人の街へ行く
8. いいねを送る

## 13. リスクと対策

| リスク | 対策 |
|---|---|
| バックエンド待ち | 初日から同一形式のモックAPIを使う |
| ドラッグ操作が不安定 | タップ選択＋タップ配置に限定 |
| 画像サイズが揃わない | 1マス64px、基準点を下中央へ統一 |
| API接続で値がずれる | 成功レスポンスで全関連値を更新 |
| 作業量が多い | Must完了までランキング演出等を後回し |
