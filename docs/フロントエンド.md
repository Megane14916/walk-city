# Walk City フロントエンド設計書

## 1. この文書の目的

Walk City の React フロントエンドが担当する範囲、画面、状態、バックエンドとの境界を定義する。

ゲームルールと残高・人口などの確定値はバックエンドを正とする。価格、歩数からコインへの変換率、建物効果など、調整される値をフロントエンドへハードコードしない。

## 2. 技術構成

- React
- TypeScript
- Vite
- Supabase JavaScript Client
- Supabase Auth（Google ログイン）

ルーティング、データ取得ライブラリ、テストツール、マップ描画方式は未選定（TBD）。ハッカソン期間とチームの習熟度を優先して決定する。

## 3. フロントエンドの責務

- Google ログインの開始、ログアウト、セッション復元
- 今日の歩数、所持コイン、人口の表示
- 歩数同期操作と同期結果・エラーの表示
- 建物・道路カタログと価格・効果の表示
- 建物・道路の購入、配置、移動操作
- 最大 100×100 のマップ表示と開放済み範囲の表現
- 建築可能・不可能なセルのプレビュー
- 全ユーザー人口ランキングの表示
- 他ユーザーの街の閲覧
- ローディング、空状態、通信失敗、再試行の UI
- API の型定義と、フロントエンド開発用モックの維持

次の処理はフロントエンドで確定しない。

- Google Health から取得した歩数の正当性
- 歩数から付与するコイン数
- 購入可否とコイン減算
- 建築可能範囲、道路隣接、他建物との衝突判定
- 建物効果と人口の計算
- 土地開放条件の達成判定
- ランキング順位

## 4. 主要画面

### 4.1 ログイン画面

- Google でログインするボタン
- 認証中・認証失敗状態
- 初回ログイン時のプロフィール作成導線（必要項目は TBD）

### 4.2 ホーム画面

- Google Health から最後に同期した日時
- 今日の歩数
- 所持コイン
- 街の人口
- 歩数同期ボタン
- 街づくり、ランキングへの導線

歩数同期は Edge Function を呼び出す。クライアントから歩数値を送信して残高を直接変更する設計にはしない。

### 4.3 街づくり画面

- 自分の街のグリッド
- 開放済み範囲と未開放範囲
- 配置済みの建物と道路
- 建物ショップ
- 建物の詳細（大きさ、価格、効果）
- 購入・配置モード
- 配置済み建物の移動モード
- 現在のコインと人口

配置操作の基本状態は次のとおりとする。

```text
idle
  -> selecting-item
  -> previewing-position
  -> submitting
  -> succeeded | failed
  -> idle
```

購入と配置はサーバー上の一つの処理として実行する。画面上で仮配置する場合も、API が拒否したら必ずサーバーの状態へ戻す。

### 4.4 ランキング画面

- 全ユーザーの人口順位
- 表示名、街名、人口
- 自分の順位の識別
- ユーザーを選択して街を訪問する導線
- ページングまたは取得件数は TBD

### 4.5 他ユーザーの街

自分の街と同じマップ表示コンポーネントを閲覧専用で使用する。購入、配置、移動、土地開放の操作は表示しない。

## 5. マップ UI

### 5.1 座標とサイズ

- マップ全体: 最大 100×100 セル
- 初期開放範囲: 20×20 セル
- 原点: 左上 `(0, 0)`
- `x`: 右方向、`y`: 下方向
- 標準セル: 1×1
- 配置物: 1×1 または 2×2
- 回転: 不可
- 移動: 可

2×2 の配置物は左上セルをアンカー座標とする。例えば `(3, 4)` に置かれた 2×2 建物は、`(3,4)`、`(4,4)`、`(3,5)`、`(4,5)` を占有する。

### 5.2 表示と操作

- 100×100 を常時すべて DOM 要素として描画するかは性能検証後に決める。
- スマートフォンではパン・ズームまたは表示範囲の切り替えを提供する（具体的操作は TBD）。
- 選択中の建物サイズに合わせて占有予定セルを強調する。
- API 呼び出し前の判定は操作補助として行うが、最終判定はバックエンドへ委ねる。
- 回転 UI は設けない。
- 移動は、配置済み建物を選択して移動先を指定する方式を基本とする。
- 建物削除は仕様決定まで UI を設けない。
- 障害物は仕様決定までデータ型だけを許容し、存在を前提にしない。

道路の「周辺」の定義（上下左右のみ、斜めを含む等）は未確定である。API が返す配置可否を表示できるようにし、フロント独自の規則を固定しない。

## 6. 建物カタログの表示

建物一覧は API から取得し、次の値をデータとして扱う。

| 種別 | 表示名 | サイズ | 現時点の効果 |
|---|---|---:|---|
| `small_house` | 住宅（小） | 1×1 | 人口 +10 |
| `small_park` | 公園（小） | 1×1 | なし（将来追加可能） |
| `hospital` | 病院 | 2×2 | なし（将来追加可能） |
| `commercial` | 商業施設 | 1×1 | 歩数によるコイン獲得量を増加。増加量は TBD |
| `farm` | 農場 | 2×2 | 人口 +5 |
| `road` | 道路 | 1×1 | 周辺への建築を可能にする。隣接ルールは TBD |
| `town_hall` | 役所 | 2×2 | 住宅（小）1軒あたりの人口を +20。適用範囲・重複ルールは TBD |
| `factory` | 工場 | 2×2 | 歩数によるコイン獲得量を増加。増加量は TBD |

コストはすべて TBD である。住宅（小）の基礎人口は10人とし、役所の効果が適用される場合は1軒あたりさらに20人増加する。役所の適用範囲と複数設置時の重複ルールは API の設定を正とする。

フロントエンドは `effects` の未知の種類を無視しても画面全体が壊れないようにし、既知の効果だけを説明文へ変換する。API から人間向けの `description` も受け取り、未知の効果を表示できる形が望ましい。

## 7. 推奨ディレクトリ構成

現在の実装が初期状態のため、機能単位で次のように分割する。

```text
frontend/src/
├── app/                  # ルーティング、プロバイダー、共通レイアウト
├── features/
│   ├── auth/
│   ├── health/
│   ├── town/
│   └── ranking/
├── components/           # 複数機能で共有する UI
├── lib/
│   ├── supabase.ts
│   └── api-error.ts
├── mocks/                # API 契約に沿ったモック
├── types/                # API の共有型
└── assets/
```

## 8. データ取得と状態管理

### サーバー状態

- 認証ユーザー
- 歩数同期状態
- コイン残高
- 自分の街
- 建物カタログ
- ランキング
- 訪問先の街

これらは API レスポンスを正とし、更新成功後は関連データを再取得するか、成功レスポンスのスナップショットで更新する。

### 画面内の一時状態

- 選択中のカタログ項目
- 配置・移動モード
- プレビュー座標
- ズームと表示位置
- モーダルの開閉
- 送信中状態

コインと人口を複数コンポーネントで独立計算しない。

## 9. API 境界

フロントエンドが使用する操作は [API計画書.md](./API計画書.md) を正とする。最低限、次のサービス関数を用意する。

```ts
signInWithGoogle()
signOut()
getDashboard()
syncSteps()
getBuildingCatalog()
getMyTown()
placeBuilding(input)
moveBuilding(input)
getPopulationRanking(input)
getPublicTown(userId)
```

Supabase SDK、RPC、Edge Function の呼び出しをコンポーネントへ直接散在させず、機能ごとの API 層に集約する。

## 10. モック開発

バックエンドと並行開発するため、API 型と同じ次のモックケースを用意する。

- 未ログイン、ログイン済み、初回ユーザー
- 歩数未同期、同期成功、権限不足、外部 API 失敗
- コイン不足
- 1×1 と 2×2 の配置成功
- マップ外、未開放、他建物と重複、道路条件未達による配置失敗
- 建物移動成功・失敗
- ランキングと他ユーザーの街
- 空のランキング

## 11. エラーと再送

- 認証切れ: 再ログインを案内する。
- Google Health 権限不足: 権限付与または再連携を案内する。
- 同期失敗: コイン表示を推測で更新せず再試行を提供する。
- 配置失敗: 理由を表示し、確定前の仮配置を取り消す。
- コイン不足: 最新残高を反映する。
- 競合: 街データを再取得して表示を同期する。
- 不明なエラー: 一般メッセージと再試行を表示し、詳細を画面へ露出しない。

## 12. テスト観点

- 認証後にセッションが復元される。
- 歩数同期を連打しても二重にコインが付与された表示にならない。
- 100×100 の端でも座標と表示がずれない。
- 2×2 建物の占有セルが正しい。
- 開放範囲外、重複、道路条件未達を適切に表示する。
- 1×1 と 2×2 の建物を移動できる。
- 回転操作が存在しない。
- 他ユーザーの街を編集できない。
- API から価格・効果が変わっても表示へ反映される。
- スマートフォンでマップとショップを操作できる。
- ローディング、空状態、エラー状態から復帰できる。
